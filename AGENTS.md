# Repos Root, Multi-Brain Workspace (Codex orientation)

This is the Codex mirror of `CLAUDE.md`. The two files carry the same content and must be edited
together. Orient from this file first.

This is the repos root: the shared-parent tier of the Infinite Brain topology, and the folder you open.
Its job is to route your work to the right brain and keep every brain synced. There are two ways to run
it, and they compose. The primary shape is a multi-brain workspace: a few brains mounted under `brains/`
that you work across. The secondary shape is a registry root for an operation that runs many repos.

## The workspace: brains mounted under `brains/`

`brains/` holds the brains you work across, each an independent git repo cloned in by `/start`:

- a shared brain (a company brain, or a graduated department brain): the default working surface;
- your individual brain (`individual-<name>/`): your own scratch and research layer.

If `brains/` is empty, run `/start` and it clones your brains in.

### Routing rule

1. **Default to the shared brain** for real, shared, or canon-reading work. Reference its canon by path,
   never copy it.
2. **Individual brain for anything new, uncertain, or disruptive.**
3. **Proven individual work is promoted up**, never edited into the shared brain directly; `/sync` routes
   a core change to a `proposal/<slug>-<topic>` branch for review.

`.claude/CAPABILITIES.md` (regenerated by `/sync`) lists what each mounted brain holds so you can route
work to the right brain.

### Commands

- `/start`: establish git access (GitHub by default), clone or refresh every brain under `brains/`, run `/sync`.
- `/sync`: push the individual brain freely; push shared-brain content to the shared branch; route
  shared-brain core changes to a proposal branch; pull the latest; refresh the copied command layer and
  the capability index.
- `/save`: commit every brain, no push. `/promote-to-department`: package individual work for review.
  `/workspace-help`: plain-words explanation.

### How a brain's own commands work here

Claude Code (and Codex) load only this root's adapter folder, never a child repo's. So `/start` and
`/sync` copy each mounted brain's `.claude/{commands,skills,agents,rules}` up into this root, so a
brain's tools become commands here (after a restart). A copied command runs against its source brain
(see `.claude/COPIED-FROM.md`). The workspace's own commands are never overwritten.

## The registry root (secondary: running many repos)

An operation running more than the handful of mounted brains plus app repos also uses this root as a
registry. Children live under `internal/` (owned) and `external/` (client-owned or co-operated, grouped
under `external/<group>/`), each an independent repo known only through a `repo-registry/` entry.
`repo_kind` is `brain`, `app`, or `mixed`; a brain also carries `brain_tier` (`individual`, `department`,
`company`). Register via `ADD-A-BRAIN.md` or the `register-repo` command. The registry is the full map;
`brains/` is the subset you actively work across.

## What this root never carries

No brain content of its own. The brains under `brains/` and the children under `internal/`/`external/`
are independent repos with their own remotes; this root git-ignores their contents and provides no
backup. The copied command layer and the capability index are generated, git-ignored, regenerated by
`/sync`, read-only downstream, never a second source of truth. No secret value lives here.
