# Repos Root, Multi-Brain Workspace (Claude Code orientation)

This is the repos root: the shared-parent tier of the Infinite Brain topology, and the folder you open
in Claude Code. Its job is to route your work to the right brain and keep every brain synced. Orient
from this file first. `AGENTS.md` is the Codex mirror; keep the two in sync.

There are two ways to run this root, and they compose. The primary shape is a multi-brain workspace: a
few brains mounted under `brains/` that you work across every day. The secondary shape is a registry
root for an operation that runs many repos. Most people want the workspace.

## The workspace: brains mounted under `brains/`

`brains/` holds the brains you work across, each an independent git repo cloned in by `/start`:

- a shared brain (a company brain, or a department brain that graduated to its own repo): the default
  working surface, the canon everyone relies on;
- your individual brain (`individual-<name>/`): your own scratch and research layer, fewer guardrails.

If `brains/` is empty, this is a fresh machine: run `/start` and it clones your brains in.

### Routing rule (which brain gets the work)

1. **Default to the shared brain** for real, shared, or canon-reading work. Read its canon; never copy
   it into another brain, reference it by path.
2. **Individual brain for anything new, uncertain, or disruptive.** If the work might be wrong or could
   break what others rely on, it starts in your individual brain. Cheap to be wrong there.
3. **Proven individual work is promoted up, never edited into the shared brain directly.** `/sync`
   routes any core change to the shared brain onto a `proposal/<slug>-<topic>` branch for review.

`.claude/CAPABILITIES.md` (regenerated by `/sync`) lists what each mounted brain holds, its tools,
workflows, agents, skills, and knowledge, with a one-line when-to-use, so you can direct work to the
right brain concretely rather than guessing.

### Commands

- `/start`: set up or wake up this machine. Establish git access (GitHub by default), clone or refresh
  every brain under `brains/`, then run `/sync`.
- `/sync`: back up your work and get the latest. Push your individual brain freely; push shared-brain
  content (outputs, sessions) to the shared branch; route shared-brain core changes to a
  `proposal/<slug>-<topic>` branch for review; pull the latest; refresh the copied command layer and the
  capability index from every brain.
- `/save`: commit your work in every brain with your name on it, without pushing.
- `/promote-to-department`: package something from your individual brain for review.
- `/workspace-help`: explain the workspace in plain words.

### How a brain's own commands work here

Claude Code loads only this root's `.claude/`, never a child repo's. So `/start` and `/sync` copy each
mounted brain's `.claude/{commands,skills,agents,rules}` up into this root's `.claude/`, so a brain's
own tools become slash commands here. They load after a Claude Code restart. A copied command runs
against its source brain, so it changes into that brain's folder first (see `.claude/COPIED-FROM.md`).
The workspace's own commands above are never overwritten.

## The registry root (secondary: running many repos)

When an operation runs more than the handful of brains it mounts under `brains/`, plus app repos
(product and client codebases), it also uses this root as a registry. Child repos live under `internal/`
(repos this operation owns) and `external/` (client-owned or co-operated repos, grouped under
`external/<group>/`), each an independent git repo the harness ignores and knows only through a
`repo-registry/` entry. `repo_kind` is `brain`, `app`, or `mixed`; a brain also carries a `brain_tier`
of `individual`, `department`, or `company`. To register a repo, follow `ADD-A-BRAIN.md` or run the
`register-repo` command. An app repo is an ordinary sibling with no brain ontology and no tier.

The registry is the full map of what lives at this root; `brains/` is the subset you actively work
across. A brain mounted under `brains/` may also carry a registry entry when the operation wants it in
the full inventory.

## What this root never carries

No brain content of its own: no knowledge, doctrine, or entities authored here. The brains under
`brains/` and the child repos under `internal/`/`external/` are independent git repos with their own
remotes and history; this root git-ignores their contents and provides them no backup. Each brain's
backup story is its own remote. The copied command layer and the capability index are generated,
git-ignored, and regenerated by `/sync`; they are read-only downstream and never a second source of
truth. No secret value lives here.
